# Benchmarks

Every `benchmark_<technique>.py` runs the same harness ([harness.py](harness.py)) and reports, for each
implementation on each dataset, **speed, peak memory and accuracy** against the technique's reference. Nothing here is
collected by pytest, and no benchmark is a gate: pytest (`tests/test_<technique>.py`) is the correctness gate.

Run one with the project's Python, from the repository root:

```
python tests/performance/benchmark_<technique>.py      # with the project's p312 env's Python
```

Results are written to `tests/performance/results/<technique>_<timestamp>.arrow` (Arrow IPC, ZSTD; git-ignored).
Each row is one (dataset, implementation, variant, threads) measurement, run in its own child process. Rust
implementations run at N threads and at 1 thread, which gives the algorithmic, parallel and total speedups.
Estimators (sketches) are scored against the reference and against their exact Rust sibling where one exists
(`exact_rust_*`, `speedup_vs_exact_rust`).

"N×M" below means N rows by M columns. Datasets come from `synthdata` (`services/datagen`): `cover(50 000)` is the
covering frame at 50 000 rows (`synthdata.cover.cover`, via `harness.cover_dataset`: 77 columns — the pairwise
covering design over family, cardinality, skew, nulls, order and structure, a planted-relations block and nested
extras); the other shapes are `synthdata.scenarios` functions (`describe_narrow`, `describe_wide`,
`describe_nested`, `integer_multiples`, `integer_random`, `runs_int`, `runs_str`, `low_cardinality`, `near_unique`,
`near_constant`, `related_frames`, `similar_frames`, `population_samples`, `top_k_streams`).

## Technique benchmarks

| Technique (script) | Purpose | Module benchmarked | Reference | Datasets |
|---|---|---|---|---|
| **GCD** (`benchmark_gcd.py`) | Finds the greatest common divisor of an integer column's raw values, which ClickHouse's GCD codec can exploit. | `techniques.gcd`: `GcdRust` against `GcdNumpy` and `GcdMath` | `GcdMath`: pure Python, `math.gcd` over `to_list()`, single core, arbitrary precision. `GcdNumpy` (`np.gcd`) is the other non-Rust competitor. | `cover(50 000)`; narrow 10M×4 Int64 multiples of 3 600; wide 1M×100 Int64 multiples of 3 600; early-exit 10M×4 random Int64 (GCD 1). `GcdMath` is excluded from the last three because `to_list()` would exhaust memory. |
| **Describe** (`benchmark_describe.py`) | Profiles each column (counts, lengths, cardinality estimates, IPC sizes) to help choose narrower or more compressible Arrow types. | `techniques.describe`: `DescribeRust` against `DescribeDataFusion` and `DescribePolars` | `DescribePolars`: Polars expressions per column, pyarrow for sizes, columns one after another. `DescribeDataFusion` runs Apache DataFusion SQL. | `cover(50 000)`; narrow 10M×4 (int, float, numeric string, ISO datetime string); wide 1M×100 (cycling Int64 / Float64 / String / Date); nested 1M×3 (List(Int64), List(String), Struct). |
| **Top-k** (`benchmark_top_k.py`) | Finds each column's k most frequent values with approximate sketches. | `techniques.top_k`: `TopKHeavyKeeperRust` and `TopKSpaceSavingRust` against `TopKPolars` | `TopKPolars`: exact counts by Polars `group_by`, holding every distinct value. Scored against exact counts. | `cover(50 000)`; narrow 10M×4 (1 000 values); wide 200K×100 (1 000 values); six 10M×1 streams (Zipf α 1.5 / 1.1 / 0.8, flat, skewed, string). Variants: k ∈ {5, 256} × memory ¼×, 1×, 4× the default. `--rows N` runs one `zipf_11` stream at N rows. |
| **Distinct count** (`benchmark_distinct_count.py`) | Estimates how many distinct non-null values each column holds, with an interval. | `techniques.distinct_count`: `DistinctCountHllRust` and `DistinctCountPolarsApprox` | `DistinctCountPolars`: exact Polars `n_unique` of the canonical non-null values. Variants: HLL precision 10 / 12 / 14 / 16 (`PolarsApprox` ignores it). | `cover(50 000)`; narrow 10M×4 Int64 (10³ / 10⁵ / 10⁶ / 10⁷ values); wide 1M×100 (Int64 / Float64 / String / Date); strings 10M×2 (10⁶ and 10⁷ labels). |
| **Population cardinality** (`benchmark_population_cardinality.py`) | Estimates the distinct values in the population behind a sample (Chao1, Schnabel), including unseen ones. | `techniques.population_cardinality`: `PopulationCardinalityRust` | `PopulationCardinalityPolars`: Polars `group_by` counts, a NumPy SplitMix 3-way split, the Python estimators. Also scored against the known population size (`observed_rel_err`, `chao1_rel_err`, `schnabel_rel_err`, coverage). | `cover(50 000)`; samples of 1M and 100K rows × 8 columns drawn from populations of 10³ / 10⁴ / 10⁵ / 10⁶ labels, uniform and Zipf 1.1 (known truth). |
| **Marginal entropy** (`benchmark_marginal_entropy.py`) | Computes each column's Shannon entropy, null as a category. | `techniques.marginal_entropy`: `MarginalEntropyRust` (exact) and `MarginalEntropyAmsRust` (AMS sketch) | `MarginalEntropyPolars`: Polars `value_counts` plus entropy, one column at a time. The AMS sketch is also scored against `MarginalEntropyRust`. | `cover(50 000)`; narrow 2M×4; wide 20K×60; near-unique 1M×9; near-constant 1M×3 (the pairwise-entropy shapes). |
| **Runs test** (`benchmark_runs_test.py`) | Tests whether equal consecutive values cluster more than chance, which marks candidates for run-end encoding. | `techniques.runs_test`: `RunsTestRust` | `RunsTestPolars`: neighbour comparison with `ne_missing`, a group-by for category counts, exact Python-int moments. Shares no code with the Rust kernel. | `cover(50 000)`; long runs 10M×4 (mean run 1 000, 2 int + 2 string); random 10M×4 (every row its own run); wide 1M×100 (mean runs 1 / 10 / 100 / 1 000). |
| **Delta** (`benchmark_delta.py`) | Measures how well ClickHouse's Delta and DoubleDelta codecs suit an integer column in its row order. | `techniques.delta`: `DeltaRust` | `DeltaPolars`: Python-int differences, byte widths by explicit bounds, entropy from a `Counter`, baseline by `bisect`. Slow, so the shapes are smaller. | `cover(50 000)`; timestamps 1M×4 (regular step plus jitter, ms); wide 20K×100 (random walks of varying step size). |
| **MinMax index** (`benchmark_minmax_index.py`) | Estimates how many point queries a `minmax` skip index would skip, in stored and random row order. | `techniques.minmax_index`: `MinMaxIndexRust` | `MinMaxIndexPolars`: rank ids by join, Polars `rolling_min` / `rolling_max`, baseline in Python floats. Shares no code with the Rust kernel. | Window 8 192 rows. `cover(50 000)`; clustered 10M×4 (runs ≈ 1 000, 1 000 values, int + string); random 10M×4 (100 000 values); wide 1M×100 (mean runs 1 / 10 / 100 / 1 000). |
| **Set index** (`benchmark_set_index.py`) | The same for `set(max_size)` skip indexes. | `techniques.set_index`: `SetIndexRust` | `SetIndexPolars`: occurrence intervals in Polars, summed with a NumPy difference array, baseline in Python floats. Shares no code with the Rust kernel. | Same four datasets as the MinMax benchmark. Window 8 192, `max_size` 100. |
| **Membership** (`benchmark_membership.py`) | Measures directional containment of distinct values between columns, to spot primary-key and foreign-key relationships. | `techniques.membership`: `BloomRust` and `BloomFastbloom` | `MembershipExact`: Python `frozenset` intersection of distinct values. `BloomFastbloom` (`fastbloom_rs`) is the other non-Rust competitor. | `cover(50 000)`; related 3 frames × 1M rows; related 3 frames × 50K rows; wide 2 frames × 100 columns (50 similar, 50 independent, 100 000 elements). |
| **Similarity** (`benchmark_similarity.py`) | Computes Jaccard and overlap between columns, pruning pairs probabilistically before exact verification. | `techniques.similarity`: `MinHashRust` | `SimilarityExactLRU`: brute-force exact Jaccard and overlap through a per-instance LRU cache of distinct-value sets. `MinHashDatasketch` (`datasketch`) is the other competitor. | `cover(50 000)`; related 3 frames × 1M rows; medium 2 frames × 20 columns; wide 2 frames × 100 columns. |
| **Chi-squared** (`benchmark_chi_squared.py`) | Tests independence between column pairs, with Cramér's V as the effect size. | `techniques.chi_squared`: `ChiSquaredRust` | `ChiSquaredScipy`: `scipy.stats.chi2_contingency` on a dense table. `ChiSquaredPolarsDS` (`polars_ds`) is the other competitor. | `cover(50 000)`; narrow 2M×4; wide 20K×60. The last two are Int64 columns of 20 values, 5% null, every 5th a noisy copy of the previous. |
| **Pairwise entropy** (`benchmark_pairwise_entropy.py`) | Computes joint entropy and mutual information between column pairs to find redundant columns. | `techniques.pairwise_entropy`: `PairwiseEntropyRust` (exact) and `PairwiseEntropyAmsRust` (AMS sketch) | `PairwiseEntropyPolars`: Polars `value_counts` plus entropy over a 2-field struct, one pair at a time. The AMS sketch is also scored against `PairwiseEntropyRust`. | `cover(50 000)`; narrow 2M×4; wide 20K×60; near-unique 1M×9; near-constant 1M×3. |
| **Threeway entropy** (`benchmark_threeway_entropy.py`) | Computes joint entropy of column triplets to find near-unique combinations. | `techniques.threeway_entropy`: `ThreewayEntropyRust` and `ThreewayEntropyAmsRust` | `ThreewayEntropyPolars`: Polars `value_counts` plus entropy over a 3-field struct, one triplet at a time. The AMS sketch is also scored against `ThreewayEntropyRust`. | `cover(50 000)` first 40 columns; `cover(50 000)` all 77 columns (73 150 triplets; Polars and AMS excluded); narrow 1M×5; wide 20K×30; near-unique 1M×9; near-constant 1M×3. |
| **Adjusted Rand** (`benchmark_adjusted_rand.py`) | Measures chance-corrected agreement between two columns' groupings, i.e. whether they define the same partition. | `techniques.adjusted_rand`: `AdjustedRandRust` | `AdjustedRandSklearn`: scikit-learn `adjusted_rand_score` on string labels. | `cover(50 000)`; narrow 2M×4; wide 20K×60 (same generators as chi-squared). |

## Other benchmark scripts

| Script | Purpose | Module benchmarked | Reference | Datasets |
|---|---|---|---|---|
| `benchmark_recommend.py` | Times the recommenders and checks the frequency-ordered dictionary against the first-seen order. | `recommenders.OneShotRecommender` and `StreamingRecommender` | No accuracy reference. A Polars top-k oracle is timed as a baseline, and pyarrow `dictionary_encode` is the baseline for dictionary size. | `cover(50 000)`; narrow 1M×4; wide 50K×100; Zipf 1M×4 (text columns with 50 / 500 / 5 000 values, plus a Categorical). Streaming batches of 10 000 and 100 000 rows. |
| `benchmark_streaming_entropy.py` | Compares the sample and AMS entropy estimators past the exact phase. | `StreamingRecommender` (`entropy_estimator` `sample` vs `ams`) | Exact entropy from `OneShotRecommender` on the same data. | 1M-row single columns: uniform over 10⁴ / 10⁵ / 10⁶ values; Zipf 0.8 / 1.1 / 1.5; near-constant (99.9% zeros); plus `cover(50 000)`. |
| `calibrate_clickhouse_sizes.py` | Compares the ClickHouse size emulator's predicted bytes with bytes measured on a live server. | `common/clickhouse_sizes.rs` through `recommenders` | Measured ClickHouse bytes via chbench; needs the `chbench-ch` container. | `cover(50 000)`; GCD frames, 1M rows each: UInt64 multiples of 1 000, even UInt64, Int64 multiples of 3, Datetime(us) whole seconds; Delta frames, 1M rows each: regular and jittered Datetime(ms) timestamps (1% gaps), an Int64 random walk, sorted UInt64 ids, Int16 and Int32 walks, random Int64. |
| `calibrate_skip_indexes.py` | Compares predicted skip shares and index bytes with ClickHouse. | The skip-index recommenders | Measured ClickHouse results via chbench; same requirements. | Known-answer frames, 1M rows each: sorted ids, clustered (runs of 1 000), random over 50 values, grouped hashes (runs of 10); plus `cover(200 000)`. Point queries only, granule 8 192 rows. |
| `spike_clickhouse_delta.py` | Checks the Delta, DoubleDelta and GCD on-disk layout against ClickHouse. | The emulator, via `_plugin.clickhouse_profile` | `data_compressed_bytes` from a live ClickHouse table; same requirements. | 16 generated columns × 11 codec chains. |
| `spike_datafusion_ree.py` | Shows which DataFusion operators accept run-end-encoded columns. Re-run after a DataFusion upgrade. | DataFusion (not this project's code) | The same query on plain (non-REE) data. | A small generated table with Int64 and Utf8 columns and nulls. |

Where a reference is "Polars" it is exact but not always fast. The Delta, Runs test, MinMax and Set references are
deliberately written to share no code with the Rust kernels.
